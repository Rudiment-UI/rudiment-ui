# Theming

Rudiment UI's theming system is built on CSS custom properties generated from JSON token files. You can change every visual decision without touching component code.

## How theming works

Rudiment UI generates CSS files from your token definitions:

| File | Selector | Purpose |
|---|---|---|
| `tokens/build/tokens.css` | `:root` | Base (light) theme |
| `tokens/build/tokens-dark.css` | `[data-theme="dark"]` | Dark theme overrides |
| `tokens/build/tokens-roomy.css` | `[data-theme="roomy"]` | Roomy light theme |
| `tokens/build/tokens-roomy-dark.css` | `[data-theme="roomy-dark"]` | Roomy dark theme |
| `tokens/build/tokens-soft.css` | `[data-theme="soft"]` | Soft light theme |
| `tokens/build/tokens-soft-dark.css` | `[data-theme="soft-dark"]` | Soft dark theme |
| `tokens/build/tokens-compressed.css` | `[data-theme="compressed"]` | Compressed light theme |
| `tokens/build/tokens-compressed-dark.css` | `[data-theme="compressed-dark"]` | Compressed dark theme |

When a `data-theme` attribute is set on an ancestor element, CSS custom properties resolve to that theme's values. Components don't need any conditional logic because the cascade handles everything.

## Customizing your brand

### Change the brand color

Edit `tokens/semantic.json` to point brand tokens at a different primitive:

```json
{
  "color": {
    "brand": {
      "primary": {
        "$value": "{color.blue.600}",
        "$type": "color"
      },
      "primary-hover": {
        "$value": "{color.blue.700}",
        "$type": "color"
      }
    }
  }
}
```

Every component that uses `--rudi-color-brand-primary` (buttons, links, focus rings) will update automatically.

### Change the color palette

To use an entirely different palette, edit the primitive values in `tokens/tokens.json`. For example, replace the blue ramp with your brand hues:

```json
{
  "color": {
    "blue": {
      "50":  { "$value": "#EFF6FF", "$type": "color" },
      "100": { "$value": "#DBEAFE", "$type": "color" },
      "500": { "$value": "#3B82F6", "$type": "color" },
      "600": { "$value": "#2563EB", "$type": "color" },
      "700": { "$value": "#1D4ED8", "$type": "color" },
      "900": { "$value": "#1E3A8A", "$type": "color" }
    }
  }
}
```

Then rebuild:

```bash
npm run build:tokens
```

### Adjust typography

Font families, sizes, weights, and line heights are all token-driven. Edit `tokens/tokens.json`:

```json
{
  "font": {
    "family": {
      "sans": { "$value": "'Inter', system-ui, sans-serif", "$type": "fontFamily" },
      "mono": { "$value": "'JetBrains Mono', monospace", "$type": "fontFamily" }
    }
  }
}
```

### Adjust spacing and radii

Spacing and border-radius tokens follow the same pattern:

```json
{
  "spacing": {
    "4": { "$value": "1rem", "$type": "dimension" }
  },
  "radius": {
    "md": { "$value": "0.375rem", "$type": "dimension" }
  }
}
```

## Dark mode

### Enabling dark mode

Set the `data-theme` attribute on your root element:

```html
<html data-theme="dark">
```

### Respecting system preference

Detect the user's OS-level setting and apply the matching theme:

```js
function applyTheme() {
  const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches
  document.documentElement.setAttribute('data-theme', prefersDark ? 'dark' : 'light')
}

// Apply on load
applyTheme()

// React to changes
window.matchMedia('(prefers-color-scheme: dark)')
  .addEventListener('change', applyTheme)
```

### Theme toggle in React

A minimal toggle that cycles through all built-in themes:

```tsx
import { useState, useEffect } from 'react'

const themes = [
  'light', 'dark',
  'roomy', 'roomy-dark',
  'soft', 'soft-dark',
  'compressed', 'compressed-dark',
] as const

function ThemeToggle() {
  const [theme, setTheme] = useState(() =>
    document.documentElement.getAttribute('data-theme') || 'light'
  )

  useEffect(() => {
    document.documentElement.setAttribute('data-theme', theme)
  }, [theme])

  const next = () =>
    setTheme(t => themes[(themes.indexOf(t) + 1) % themes.length])

  return <button onClick={next}>Theme: {theme}</button>
}
```

If your app only needs light and dark mode, simplify the toggle to switch between two values instead.

### Persisting the user's choice

Store the selected theme in `localStorage` so it survives page reloads:

```js
// Read on load
const saved = localStorage.getItem('rudi-theme')
const systemPref = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
const theme = saved || systemPref

document.documentElement.setAttribute('data-theme', theme)

// Save on change
function setTheme(value) {
  document.documentElement.setAttribute('data-theme', value)
  localStorage.setItem('rudi-theme', value)
}
```

This approach works with any `data-theme` value, so it handles custom themes you add later without changes.

### Customizing dark mode tokens

Dark mode overrides live in two files:

- `tokens/themes/dark/semantic.json` — colors for text, backgrounds, borders, and feedback states
- `tokens/themes/dark/components.json` — component-specific overrides (only needed when a component should differ beyond what semantic tokens provide)

Edit these files and rebuild:

```bash
npm run build:tokens
```

You only need to define tokens that differ from the light theme. Any token not overridden inherits its light value.

## Creating additional themes

The same pattern used for dark mode extends to any number of themes. Here's how to add a high-contrast theme as an example:

1. Create a new directory under `tokens/themes/` with your theme name:

   ```
   tokens/themes/high-contrast/
     semantic.json
     components.json   # optional
   ```

   Define only the tokens that differ from the base theme.

2. Copy `tokens/style-dictionary.config.dark.mjs` and adjust it for your new theme:

   ```js
   // tokens/style-dictionary.config.high-contrast.mjs
   export default {
     source: [
       'tokens/tokens.json',
       'tokens/semantic.json',
       'tokens/components.json',
       'tokens/themes/high-contrast/**/*.json',
     ],
     platforms: {
       css: {
         transformGroup: 'css',
         buildPath: 'tokens/build/',
         files: [{
           destination: 'tokens-high-contrast.css',
           format: 'css/variables',
           options: {
             selector: '[data-theme="high-contrast"]',
           },
         }],
       },
     },
   }
   ```

3. Add the build step to your `build:tokens` script, then import the generated CSS:

   ```css
   /* src/app.css */
   @import '../tokens/build/tokens.css';
   @import '../tokens/build/tokens-dark.css';
   @import '../tokens/build/tokens-high-contrast.css';
   ```

4. Activate the theme by setting the `data-theme` attribute:

   ```html
   <html data-theme="high-contrast">
   ```

## Built-in themes

### Modifier themes: Roomy and Soft

Two themes soften the default: they warm the palette, swap in a friendlier typeface, and adjust the primitive `spacing`/`radius` scales, so the effect cascades to every component that references them, no component code required. Each ships light and dark, and every brand/text pairing meets WCAG AA contrast.

| Theme | Palette + type | Shape |
|---|---|---|
| **Roomy** (`roomy`, `roomy-dark`) | Moderately soft warm neutrals, a muted slate brand accent, and Rubik (subtly rounded) | Enlarged `spacing` scale (about 1.5x) and a slightly larger `radius` scale: more padding, wider gaps, gently rounded corners |
| **Soft** (`soft`, `soft-dark`) | Soft warm neutrals, a soft periwinkle brand accent, and Nunito (rounded, friendly) | Enlarged `radius` scale plus full-pill buttons: large rounded cards, inputs, and dialogs; spacing unchanged |
| **Compressed** (`compressed`, `compressed-dark`) | Default palette and typeface (unchanged) | Very tight `spacing` scale and very small `radius` scale: dense, near-square components |

The web fonts (Nunito, Rubik) load through `.storybook/preview-head.html`; in a production app, self-host or link them. Both themes redefine the neutral ramp and add a small brand-accent ramp, while base status colors (red/green/amber) and layout tokens cascade from `:root`.

```html
<html data-theme="roomy">
<html data-theme="soft-dark">
```

These themes work because component padding, gaps, and radii resolve through `var(--rudi-spacing-*)` and `var(--rudi-radius-*)`, and the layout primitives read their default spacing from `--rudi-layout-*` tokens that trace back to the same scale. A modifier theme redefines only those scales and re-emits the tokens that reference them; colors fall through to `:root` (light) or the dark palette (dark). Because they touch only spacing and radius, Roomy and Soft compose with any brand recolor you layer on top.

The default `light` and `dark` themes use **IBM Plex Sans** (with IBM Plex Mono for figures) and the precise, small-radius scale that gives them an IBM-style-guide feel. Roomy and Soft inherit that typeface and adjust the geometry around it.

## Overriding tokens without modifying source files

If you're consuming Rudiment UI as a dependency and don't want to fork the token files, you can override CSS custom properties directly:

```css
:root {
  --rudi-color-brand-primary: #7C3AED;
  --rudi-color-brand-primary-hover: #6D28D9;
}

[data-theme="dark"] {
  --rudi-color-brand-primary: #A78BFA;
  --rudi-color-brand-primary-hover: #8B5CF6;
}
```

This works because CSS custom properties follow normal cascade rules — a later declaration wins.

## Component-level overrides

To restyle a single component, override its component tokens:

```css
:root {
  --rudi-component-button-primary-bg: #7C3AED;
  --rudi-component-button-primary-hover-bg: #6D28D9;
  --rudi-component-button-primary-text: #FFFFFF;
}
```

This changes only the button without affecting other components that use the brand color.

## Previewing themes

Use the theme picker in the Storybook toolbar to switch between the built-in themes (Default plus the Roomy and Soft modifier themes, each in light and dark) while developing. Every story renders inside a themed wrapper, so you can verify token changes across all themes without leaving the browser.

## Advanced theming

The token system covers colors, typography, spacing, and radii, but some visual effects go beyond what a single CSS custom property can express. Two techniques let a theme reach further while still building on the token foundation.

### Custom fonts

A theme can override the sans typeface with a token in its `tokens.json`:

```json
{
  "font": {
    "family": {
      "sans": { "$value": "'Satoshi', ui-sans-serif, system-ui, sans-serif", "$type": "fontFamily" }
    }
  }
}
```

The default and dark theme configs exclude the `font` category from themed output, so a theme that overrides its typeface uses a config that lets `font.family` through:

```js
// Exclude spacing/radius/motion, but allow font-family to re-resolve per theme
const PRIMITIVE_CATEGORIES = new Set(['spacing', 'radius', 'motion'])

filter: (token) => {
  const category = token.path[0]
  if (PRIMITIVE_CATEGORIES.has(category)) return false
  if (category === 'font') return token.path[1] === 'family'
  // ... rest of filter
}
```

Load the web font in your app `<head>` (or `.storybook/preview-head.html` for Storybook). Rebuild with `npm run build:tokens` and the theme's components pick up the new typeface automatically.

### Component-level CSS treatments

Some signature effects (layered focus rings, tinted elevation, tactile press) go beyond a single token. A theme can add one such treatment in the relevant component CSS under its `[data-theme]` selector. For example, a custom `my-theme` focus ring in `button.css`:

```css
[data-theme='my-theme'] .rudi-button:focus-visible {
  outline: none;
  box-shadow:
    0 0 0 2px var(--rudi-color-background-surface),
    0 0 0 4px var(--rudi-color-border-focus);
}
```

Because these rules are scoped to `[data-theme]`, they layer cleanly on top of the base component styles and only apply when that theme is active. The same pattern works for gradients, elevation, and other effects a plain custom property cannot hold.

## End-to-end workflow

1. Edit the JSON files under `tokens/`.
2. Run `npm run build:tokens`.
3. Toggle themes in Storybook to preview your changes.
4. Import the generated CSS files in your app entry point and ship.
